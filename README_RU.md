# Commander Keen 4 — Secret of the Oracle (Go)

[English](README.md)

Нативный порт полного эпизода **Commander Keen 4 v1.4 EGA** на Go для Windows, Linux и macOS на основе восстановленного движка Omnispeak. Билли Блейз отправляется в Земли Теней, чтобы спасти восемь членов Совета Оракула. Исследуйте леса, пещеры, пирамиды и подводные области, прыгайте на пого-палке, собирайте самоцветы и припасы и оглушайте врагов нейронным бластером.

Сохранены исходные уровни, EGA-графика, спрайты, анимации, шрифты, меню, физика, поведение врагов, уровни сложности, предметы, сюжет, финал и встроенные демонстрации. Изображение формируется в исходном разрешении 320×200 с 16 цветами, масштабируется без сглаживания и отображается с пропорциями 4:3, как на ЭЛТ-мониторе. Музыка и эффекты используют оригинальные звуковые данные, перенесённый на Go синтезатор Nuked OPL3 и синтез PC Speaker.

## Управление

| Клавиша | Действие |
| --- | --- |
| Стрелки / цифровой блок | Движение, взгляд вверх/вниз, лазание по шестам; направление стрельбы |
| Ctrl | Прыжок; удерживайте для более высокого прыжка |
| Alt | Включение и выключение пого-палки |
| Пробел | Стрельба из нейронного бластера |
| Ctrl + Alt | Оригинальная комбинация стрельбы двумя кнопками |
| Enter / пробел на карте мира | Вход на уровень |
| Enter | Подтверждение выбора в меню |
| Esc | Оригинальное меню / возврат |
| F1 | Оригинальная справка, сюжет и инструкции |
| F11 | Переключение полноэкранного режима |

В разделе **Configure** оригинального меню можно изменить клавиши, звук, музыку и устройство управления. Подключённые геймпады используют исходные меню управления и калибровки джойстика. Сохранение и загрузка доступны в оригинальном меню; сложность выбирается при начале новой игры.

## Требования к сборке

Установите **Go 1.26 или новее**. При первой сборке нужен интернет для загрузки Go-модулей зафиксированных версий. Компилятор C, Cgo, пакеты разработки SDL, MinGW и отдельная игровая среда исполнения не требуются. Используйте `CGO_ENABLED=0`.

Результат сборки — **один исполнительный файл**. Для его запуска не нужно копировать рядом ресурсы, Go-модули, иконки или файлы `.syso`. Игра обращается к обычным системным API графики, ввода и звука. В Linux это библиотеки X11/OpenGL и звуковой системы рабочего стола; системные библиотеки не встраиваются в исполнительный файл. Нужны графическая среда и работающий видеодрайвер. Дополнительные DLL приложения и библиотеки SDL устанавливать не нужно.

### Подготовка иконки Windows EXE

В корне проекта, на **компьютере, где выполняется сборка**, запустите:

```sh
go mod download
go generate .
```

Включённый в проект генератор на Go читает `icon.ico` и создаёт `icon_windows_amd64.syso` и `icon_windows_arm64.syso`. Команда `go build` автоматически добавляет подходящий ресурс в Windows EXE. Генератор нужно запускать **до** установки `GOOS` и `GOARCH` для другой платформы. Эти промежуточные файлы сборки намеренно отсутствуют в архиве исходников.

`icon.png` встраивается для иконки окна на поддерживаемых платформах. У отдельного исполнительного файла macOS нет иконки приложения Finder: для неё понадобилась бы отдельная упаковка в `.app`.

### Сборка на Linux или macOS

Сначала выполните команды подготовки выше, затем выберите целевую платформу:

| Платформа | Команда |
| --- | --- |
| Windows x64 | `CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -buildvcs=false -ldflags="-s -w -H=windowsgui" -o keen4-windows-amd64.exe .` |
| Windows ARM64 | `CGO_ENABLED=0 GOOS=windows GOARCH=arm64 go build -trimpath -buildvcs=false -ldflags="-s -w -H=windowsgui" -o keen4-windows-arm64.exe .` |
| Linux x64 | `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -buildvcs=false -ldflags="-s -w" -o keen4-linux-amd64 .` |
| Linux ARM64 | `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -buildvcs=false -ldflags="-s -w" -o keen4-linux-arm64 .` |
| macOS Intel | `CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build -trimpath -buildvcs=false -ldflags="-s -w" -o keen4-macos-amd64 .` |
| macOS Apple Silicon | `CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -trimpath -buildvcs=false -ldflags="-s -w" -o keen4-macos-arm64 .` |

### Сборка на Windows — PowerShell

```powershell
go mod download
go generate .
$env:CGO_ENABLED = "0"
$env:GOOS = "windows"
$env:GOARCH = "amd64"
go build -trimpath -buildvcs=false -ldflags="-s -w -H=windowsgui" -o keen4-windows-amd64.exe .
```

Для Windows ARM64 замените `GOARCH` на `arm64`. Для сборки Linux или macOS из PowerShell установите `GOOS` в `linux` или `darwin`, выберите `amd64` либо `arm64` и используйте `-ldflags="-s -w"` вместо параметров Windows GUI.

## Запуск и сохранения

В Windows запустите EXE двойным щелчком. В Linux или macOS запустите файл своей платформы из терминала:

```sh
./keen4-linux-amd64
```

Все игровые данные встроены; текущий каталог запуска не имеет значения. Сохранения, рекорды и настройки автоматически записываются в:

| ОС | Каталог |
| --- | --- |
| Windows | `%APPDATA%\Keen4Go` |
| Linux | `$XDG_CONFIG_HOME/Keen4Go` или `~/.config/Keen4Go` |
| macOS | `~/Library/Application Support/Keen4Go` |

Это пользовательские данные, а не дополнительные компоненты для запуска. Сохранён исходный формат сохранений. Если звукового устройства нет, запускайте с параметром `--mute`; при обычном запуске музыка и эффекты настраиваются через оригинальное меню.

## Совместимость и проверка

Go-версия сопоставлена с C-версией восстановленного движка Omnispeak при воспроизведении всех четырёх оригинальных встроенных демозаписей. **Все 2953 кадра совпали попиксельно**: 827, 702, 764 и 660 кадров. Загружены все 20 записей карт; три распакованных слоя каждой карты совпали с C-движком. Файл сохранения совпал с C-версией побайтно; загрузка восстановила очки и координаты игрока. В Linux проверены нативное окно, вывод изображения, звуковой интерфейс, начало новой игры, клавиатура, переключение полноэкранного режима и корректное закрытие. Проверены шесть сборок x64/ARM64 с отключённым Cgo; Windows EXE собраны с ресурсом иконки.

Эти проверки подтверждают перенос относительно Omnispeak. Они не означают, что абсолютно каждая игровая ситуация исчерпывающе сопоставлена с исходным DOS EXE. Полное ручное прохождение и запуск на настоящих Windows и macOS в данной среде не выполнялись.
